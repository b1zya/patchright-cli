# Browser session management

A session is one daemon, one Chrome, one persistent profile, one identity. Sessions are addressed by name with `-s=<name>` (or `PATCHRIGHT_CLI_SESSION`); without a name the session is `default`.

## Named sessions

```bash
# two users of the same site, each with its own profile, cookies and proxy
patchright-cli -s=alice open https://app.example/login --proxy=http://alice.proxy:3128
patchright-cli -s=bob open https://app.example/login --proxy=http://bob.proxy:3128

patchright-cli -s=alice fill e1 "alice@example.com"
patchright-cli -s=bob snapshot
```

Each session has its own cookies, local/session storage, IndexedDB, cache, history, tabs, identity file and warning state. Sessions are scoped to the workspace (the directory that holds the `.playwright` marker, or the current directory); `list --all` shows every workspace.

## Session commands

```bash
patchright-cli list                       # sessions of this workspace
patchright-cli list --all                 # every workspace, plus browsers reachable over CDP
patchright-cli close                      # stop the default browser; the profile stays
patchright-cli -s=alice close
patchright-cli close-all
patchright-cli kill-all                   # SIGKILL stale daemons of this tool only
patchright-cli delete-data                # delete the default profile (a new identity next time)
patchright-cli -s=alice delete-data
patchright-cli -s=alice identity
```

`kill-all` matches only this tool's own daemons; browsers started by other tools on the same machine are left alone.

## Environment variable

```bash
export PATCHRIGHT_CLI_SESSION=alice
patchright-cli open https://app.example    # uses "alice"
```

## Naming

Pick a name once per task and keep it for every command of that task: a task slug plus, when several agents share a workspace, a short suffix generated by the shell, not invented by you:

```bash
SESSION="price-scan-$(openssl rand -hex 2)"
patchright-cli -s=$SESSION open https://shop.example
```

Rename nothing mid-flow; a new name is a new identity.

## Tabs vs sessions

| | tab (`tab-new` inside a session) | session (`-s=<name>`) |
|---|---|---|
| identity | shared (cookies, storage, fingerprint, proxy) | separate |
| memory | ~50-150 MB per tab | ~300-500 MB per Chrome |
| use for | several pages of the same user | different users, different proxies |

## Concurrent sessions

```bash
patchright-cli -s=site1 open https://site1.example &
patchright-cli -s=site2 open https://site2.example &
wait
patchright-cli -s=site1 snapshot
patchright-cli -s=site2 snapshot
patchright-cli close-all
```

Each `open` launches a separate Chrome (headless by default; `--headed` adds a window); keep the count reasonable for the machine. Sessions do not outlive their purpose: inside an agent harness a session closes after 30 minutes without a command or when the agent process exits (`open` announces it, `list` shows it, `<session>.watchdog.log` in the state directory records why); `--idle-timeout=<duration|0>` and `--owner-pid=<pid>` / `--no-owner-pid` adjust that per `open`, `idleTimeout` in the config per session. The daemon is never patched for this; a separate watchdog process sends it the same `close` you would.

## Attaching to an external browser

```bash
# a Chrome started with --remote-debugging-port, or a known channel with remote debugging enabled
patchright-cli attach --cdp=http://localhost:9222
patchright-cli attach --cdp=chrome
patchright-cli -s=chrome snapshot
patchright-cli -s=chrome detach            # disconnect; the external browser keeps running
```

Attached browsers were launched with somebody else's flags; the tool warns (`cdp-attach`) and cannot vouch for them. Browser servers bound by test runs (`attach <name>`) are listed by `list --all`.

## Where things are stored

- Session registry, error logs, profiles: `<cache>/patchright-cli/daemon/<workspace-hash>/` (`PATCHRIGHT_CLI_HOME` overrides the root).
- Snapshots, screenshots, videos, traces: `<workspace>/.patchright-cli/` (add it to `.gitignore`; it may contain credentials).
