# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); sections are Added, Changed, Fixed, Stealth and Upstream.

## [Unreleased]

### Added
- `env`: how to run commands on this machine — shell quoting rules (PowerShell, cmd.exe, Git Bash, POSIX), agent host and sandbox markers, writable state root, console encoding, display, host locale/timezone, default browser; `--probe` checks network access.
- `batch`: run a whole flow (open … close) from a script in one invocation, for sandboxes that kill background processes between tool calls and for permission modes that confirm every command.
- Notice `msys-path-conversion` when Git Bash turned a leading-slash argument into a Windows path.
- `wait-for-user [seconds]`: hand the visible window over to the person at the keyboard (a password the agent will not type, a one-time code, a consent dialog) and return with a fresh snapshot when the page navigates or the time runs out. Refuses when the session is headless or the display is virtual, so an agent can never ask the user to type into a browser they cannot see.
- Skill: "Adapt to the system first", "Credentials the user gives you" (one owner-provided test account entered once is ordinary QA; where to decline; the headed handover), `references/environments.md` (shell quoting, sandboxes, permission modes, security) and an English-only check next to the vendor-neutral check.
- Skill: "Headless or headed" decision policy (least intrusive mode; precedence: user preference, task requirement, environment, task-based default) and `references/platforms.md` (Linux, Windows and macOS displays, macOS privacy permissions and Gatekeeper, Apple Silicon, console windows, a diagnostics table).
- `--headful` as an alias of `--headed`; `selftest --headed`.
- Upstream layer: `vendor/cli-client/` (pristine Playwright client sources at the tag whose compiled client matches the pinned `patchright-core`, found automatically) and `vendor/playwright-cli/`; `npm run roll` now three-way merges upstream changes into `src/` through them and stops on conflicts (`.roll/conflicts/`), classifying a roll as safe / review / blocked; `--dry-run` reports without changing anything, `--check` reports a newer release and its age, `--verify` re-checks the vendored layer against upstream. `scripts/upstream-snapshot/versions.json` records the patchright-core version, the matched Playwright tag and the tracked `microsoft/playwright-cli` commit; `client.patch` is our layer as a readable diff. `npm run watch:playwright-cli` tracks the upstream CLI repository the same way.
- Workflows `upstream-roll.yml` (daily: roll on a branch, run CI, open the PR; automatic merge only for a safe roll with green CI; an issue for a blocked one) and `upstream-playwright-cli.yml` (weekly) replace the issue-only `upstream-watch.yml`; `ci.yml` is reusable with a `ref` input.
- `scripts/validate-skill.ts` (`npm run validate-skill`, part of `npm run check`): every command line in the skill parses against the CLI, the frontmatter is spec-compliant, the wording is vendor-neutral. It used to live in the git-ignored evaluation workspace, so no clone or CI run could see it.
- `scripts/session-check.mjs`: a silent session-start check (pin vs installed vs recorded version, stale build, once per new version a newer `patchright-core` on npm), wired as a `SessionStart` hook in `.claude/settings.json`.
- Session lifetime (microsoft/playwright-cli#460): `open` starts a watchdog next to the daemon that closes the browser after `--idle-timeout` without a command (config `idleTimeout`; default 30m inside an agent harness, never elsewhere) or when `--owner-pid` exits (defaults to `CLAUDE_PID` / `PATCHRIGHT_CLI_OWNER_PID` when set and alive; `--no-owner-pid` opts out). The automatic lifetime is announced on `open`, shown by `list`, logged to `<session>.watchdog.log`; `close`, `close-all`, `delete-data` and `kill-all` stop the watchdog. The daemon itself is unchanged.

### Changed
- Skill: no more references to the upstream CLI or to other tooling in the agent-facing text (the description, the intro, the command catalog, the references); "Playwright" remains only where it names a technical thing the agent must know (the `page` API in `run-code`, the protocol calls in the detection explanation, the `__playwright*` markers `selftest` looks for). SKILL.md trimmed from 500 to about 450 lines without dropping a rule: the shell rules `env` prints at runtime are no longer repeated, the command catalog is compacted, the duplicated user-agent and lifetime explanations point at the references; the two references over 100 lines start with a table of contents, and the platform notes no longer carry version-specific statements.
- `open` states the launch facts once, on its first line (browser and build, mode, profile, the presented user agent; the executable path only for a non-standard browser) and puts them into the JSON result as `launch`. The notes it prints (`headless-user-agent`, `lifetime`) are one line of facts each instead of explanations, which moved to the skill references; the client's part of a headless `open` inside an agent harness went from about 560 bytes (two explanatory notes, no facts) to about 400 (one line of facts, two one-line notes), and no later command repeats any of it. The skill gained "Where things run": paths are on demand (`list`, `identity`, `doctor`, `env`), read once per machine, quoted rather than guessed.
- Headless sessions present the headed user agent of the same Chrome build. Headless Chrome reports `HeadlessChrome/<v>` in `navigator.userAgent`, in workers and in the `User-Agent` header (three red rows on bot.sannysoft.com), while its client-hint brands, `fullVersionList`, `uaFullVersion` and platform are identical to the headed build; the major version comes from the core registry for the bundled Chromium and from the installed executable for Chrome and Edge (version directory on Windows, `Info.plist` on macOS, `--version` on Linux), and the rest is Chrome's frozen reduced user agent, applied as a context user agent (Chrome's `--user-agent` switch was measured to blank the high-entropy client hints). Note `headless-user-agent` on `open`, `--no-headless-user-agent` / `stealth.headlessUserAgent: false` to opt out, leak `headless-user-agent-unknown` when the version cannot be read; `selftest` gained a client-hint full-version check.
- `open` is headless by default. Headed is opt-in (`--headed`) for tasks that need a visible window; the mode follows flag > config `stealth.headless` > environment (no usable display means headless) > default. `--headed` with no usable display is refused with a platform-specific reason instead of an opaque Chrome launch error, and is never downgraded silently. The `headless` warning is MEDIUM and fires only together with `--proxy`; ordinary headless automation is quiet. `selftest` still measures the headed profile by default.
- `env` detects the display per platform (Linux X11/Wayland, xvfb as not human-visible; macOS Aqua session versus SSH; Windows desktop versus OpenSSH or service session) and says which mode works here.

### Fixed
- The installed-skill check depended on the line endings of the checkout: Git for Windows defaults to `core.autocrlf=true`, so a CRLF checkout compared as "out of date" against its own installed copy (the Windows CI jobs failed on it). `.gitattributes` now checks text out with LF on every platform and the fingerprint strips every carriage return.
- Without Google Chrome or Edge, the bundled Chromium counted as installed as soon as the core registry could name its path, so `open` handed the daemon a browser that was never downloaded (the registry path is the download location of the revision this `patchright-core` wants, present or not) and failed with the daemon's own "not installed" error naming the wrong tool. Only an existing executable counts now: `open`, `doctor` and `env` agree with the daemon, and a machine with no browser at all gets the `patchright-cli install-browser chromium` hint.
- `browser.launchOptions.executablePath` in the config was ignored by the channel choice: a browser outside the standard directories (a portable Chrome, a custom path) was refused on a machine without a channel, and got the user agent of a different binary on a machine with one. It is now a choice of its own (`custom-executable` warning, no channel needed, must exist, cannot be combined with `--browser`), and the headless user agent is read from that file.
- Headed sessions no longer show Chrome's "You are using an unsupported command-line flag: --disable-blink-features=AutomationControlled" bar: headed launches pass `--test-type=`, as Playwright does for its own persistent-context windows (`--disable-infobars` stopped affecting it long ago). Headless is unchanged. Verified against the public detectors from a residential IP: the CreepJS fingerprint (0% headless, 0% stealth, same hashes), Sannysoft and BrowserScan verdicts are identical with and without the switch.
- `selftest --online` opens each detector in its own tab beside the local anchor page and closes any tabs a detector spawns, so a site that redirects, opens tabs or tears down its context no longer derails the rest of the tour.
- `eval --main-world` with a bare expression (`document.title`) ran in the daemon instead of the page.
- `console` explanation, warning and docs now say precisely what is missing (`console.*` calls and uncaught exceptions, which need `Runtime.enable`) and what is still listed (browser-level log entries: failed requests, CSP violations), instead of "the Console API is disabled".

## [0.2.0] - 2026-09-05

First release as patchright-cli: the playwright-cli fork rebuilt as an anti-detection CLI for AI agents.

### Added
- Own TypeScript client (forked from playwright-cli's cli-client) driving the untouched `patchright-core` daemon; own state root, session registry, sockets and skill installer, so a playwright-cli on the same machine is never touched.
- Stealth defaults for `open`: real Google Chrome (Edge fallback), headed and maximized, persistent per-session profile, `viewport: null`, real OS color-scheme and motion preferences.
- `--proxy` with geoip: timezone, `navigator.languages`/`Accept-Language` and geolocation derived from the exit IP; WebRTC restricted to proxied routes; credentials kept off the command line and out of `config-print`.
- Identity file per profile, `identity`, `doctor` and `selftest` (38 main-world checks, `--online` detector tour).
- Leak warnings for every deviation (`--headless`, `--device`, manual geo, routes, overlays, ...), two of them unsilenceable.
- Guards: `run-code` safety scan, `eval --main-world`, `resize` moving the real window, `console` explained instead of re-enabling `Runtime.enable`, Firefox/WebKit and extension attach refused.
- Optional humanized input (`--humanize`): Bézier pointer paths with deceleration, click hold times, per-character typing.
- Layered configuration (`~/.patchright-cli/config.json`, `.playwright/patchright-cli.config.json`, `sessions.<name>`), generated daemon config, `check-drift` and `roll` tooling, CI on Windows/macOS/Linux, upstream watch.
- Agent skill rewritten around the anti-detection contract.

### Removed
- npm publishing, Microsoft-internal pipelines, Playwright test-generation references, `attach --extension`.

### Upstream
- `patchright-core` 1.62.3 (Playwright 1.62.1); client baseline `@playwright/cli` 0.1.19.
